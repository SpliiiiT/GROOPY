Section 0

Three problems, three model families

Each task has a different input shape, so each needs a different kind of model. That choice is the first thing to be able to justify.

CNN — letters

A letter is a static image of a handshape.

in: 224×224×3 image
out: 29 classes
winner: EfficientNetB0

Sequence — words

A word is a motion over time, not a picture.

in: 30 frames × 258
out: 20 classes
live: Transformer

Sentiment — text

Tone is a property of text (a word sequence).

in: a sentence
out: pos / neu / neg
ships: twitter_roberta

The common thread — the bake-off

None of these is a single hand-picked model. For each task we train several candidates under one identical protocol, then a weighted scorecard (accuracy + latency + size + robustness) picks the winner. That's how we show the engineering trade-off, not just that a model reaches some accuracy.

Model 1 · Track A

Fingerspelling CNN

Classify a cropped hand image into one of 29 classes (A–Z + del / nothing / space). Trained on Kaggle ASL Alphabet (87k images, 3000/class).

type Convolutional Neural Network input 224×224×3, [0,1] output softmax · 29 candidates 4

Architecture — the from-scratch baseline (cnn_scratch)

A compact VGG-style stack we designed ourselves — this is the "we understand CNNs" model. A conv block is [Conv2D 3×3 → BatchNorm → ReLU] ×2 → MaxPool, repeated at growing widths so the network sees ever-more-abstract features while shrinking spatially.

Gold = last conv block, the Grad-CAM target. ~1.25M parameters.

Design choices to defend

  • Two 3×3 convs per block — same receptive field as one 5×5 but fewer parameters and more non-linearity.
  • use_bias=False on convs — the following BatchNorm cancels any bias, so it's a wasted parameter.
  • BatchNorm — normalises activations → faster, more stable training.
  • GlobalAveragePooling, not Flatten — far fewer parameters (tiny model) and keeps a clean spatial map for Grad-CAM.
  • Dropout 0.4 / 0.3 — regularisation against overfitting.

The 3 transfer-learning rivals

Same head (GAP → Dropout(0.3) → Dense(29)) bolted onto an ImageNet backbone; the backbone is frozen, then its top ~30 layers are fine-tuned at LR/10 (BatchNorm kept frozen).

Results & XAI

All four reach ~99–100% — the dataset is easy, so accuracy alone can't decide. The scorecard winner is EfficientNetB0, but cnn_scratch is the real-time model (26 ms vs EfficientNet's 297 ms). XAI = Grad-CAM: gradient-weighted heatmaps confirm the model attends to the hand (not the background), and the M/A · M/E · Q/G confusions predicted at EDA show up in the heatmaps.

One-liner

"All candidates are accurate; the scorecard is really choosing on speed and size. EfficientNet wins overall, but our own cnn_scratch is the one you'd actually deploy live — the weights encode the priorities."

Model 2 · Track A

Word-sign sequence model

Classify a motion — a sequence of MediaPipe landmarks — into one of 20 word signs. Trained on 791 landmark sequences (WLASL + ASL Citizen, ~40/class).

type sequence model (RNN / Transformer) input 30 frames × 258 features output softmax · 20 candidates 4
The input — read this first

Each frame is 258 numbers from MediaPipe Holistic: pose 33×(x,y,z,vis) + left hand 21×(x,y,z) + right hand 21×(x,y,z). We stack 30 frames per sign. Before the model, normalize_sequence recenters on the shoulders and scales by shoulder width — making it position- and distance-invariant. That single step took accuracy from 5% (chance) to 70%.

  • Masking — short signs are zero-padded to 30 frames; masking makes the model ignore the padding.
  • Positional embedding — attention is order-blind, so we add a learned "which-frame" vector.
  • Self-attention — every frame can look at every other frame in parallel (why it's ~7× faster than an RNN).

XAI — gradient saliency

No image, so instead of Grad-CAM we take the gradient of the predicted class w.r.t. the input landmarks. It shows the model keys on the middle frames (the motion) and relies ~79% on the hands (left 37% + right 42%) vs ~20% on body pose — the sequence-model equivalent of "it looks at the hand."

gru vs transformer

The scorecard picks gru, but we run the transformer live: essentially tied on accuracy (74.6 vs 75.4%) yet ~7× faster (21 vs 142 ms), which matters most for the real-time capture-to-commit UX.

Model 3 · Sentiment

Sentiment classifier

Classify a sentence as positive / neutral / negative, to give signed output a "tone of voice". Three candidates: one built from scratch, two pretrained transformers.

type text classifier input a sentence output pos / neu / neg candidates 3

Architecture — the from-scratch model (scratch)

Text"this is great"
↓
TF-IDF vectorizer→ sparse features
↓
Logistic Regression→ P(positive)
↓
Neutral-band (±0.15 of 0.5)3-way
↓
label + scorepos/neu/neg

0.84 MB, trains in ~9s on CPU. Intrinsically interpretable (gold layer).

How it works

  • TF-IDF turns text into weighted word-frequency features (common-everywhere words count less).
  • Logistic Regression is a linear classifier — each word gets a weight; the sum decides positive vs negative.
  • Neutral band — IMDB has no neutral label, so a probability near 0.5 (within 0.15) is called "neutral".

The 2 pretrained rivals

  • distilbert — DistilBERT fine-tuned on SST-2 (binary movie reviews). 268 MB, PyTorch.
  • twitter_roberta — RoBERTa tuned on tweets, natively 3-class. 499 MB, PyTorch.

Note: HuggingFace dropped TensorFlow support, so both pretrained models run on PyTorch (CPU) — isolated from the rest of the TF/Keras project.

Results — the metric trap

The lesson

The raw IMDB scorecard picks distilbert — but IMDB has no neutral examples, so it can't test neutral detection. On realistic sentences distilbert gets 0/6 neutrals while twitter_roberta scores 100%. The wrong benchmark picked the wrong model — so we ship twitter_roberta.

XAI — intrinsic interpretability

The scratch model is linear, so it needs no post-hoc heatmap — you read the weights directly. Top words pushing positive: great, excellent, perfect, wonderful, amazing; pushing negative: bad, worst, awful, boring, poor. Every prediction is fully auditable.

Section 4

Why three different model types?

This is the single best question to be ready for. The answer is the input dictates the architecture:

TaskInput is…So we use…Because…
Lettersa static imagea CNNconvolutions capture 2-D spatial handshape
Wordsa motion (time series)a sequence modelRNN/attention capture how landmarks change over time
Sentimenttext (a word sequence)a linear model / transformerword features → tone; linear is also fully interpretable
And why a bake-off each time

For every task we compared a from-scratch model against stronger/pretrained ones under an identical protocol, and let a weighted scorecard choose. That's what turns "we trained a model" into "we made an engineering decision about accuracy vs speed vs size vs trust" — and each track surfaced a real insight (the deployable baseline, the speed/accuracy tie, the benchmark trap).
